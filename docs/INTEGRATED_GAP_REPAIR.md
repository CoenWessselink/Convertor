# CWS integrated gap repair

This change starts from delivered installer source `cc78a7b7`, not the older product branch.

## Scope

One project/selection -> canonical demand -> actual stock -> contour plan -> shared reservation -> persisted plan -> fresh planning PDF route. No quantities, grades, stock or machine permissions are inferred to make acceptance green.

The new installed test clicks real Qt controls on synthetic two-grade 5+3 parts, saves/reopens a project, checks stock reservations and their cancellation, renders a multi-page planning report, and rejects stale inventory. Evidence is hash-bound to the actual installed executable.

## Limits

Contour placement uses a bounded deterministic search, not a global optimality guarantee. Only explicit contours are treated as exact; bounding-box-only parts are conservative stock-planning envelopes, never production cutting contours.

Manufacturing recognition now requires useful positive recognition as well as no false-ready output. The corrected 45-category synthetic corpus is mandatory before promotion, together with recognition checks executed inside the installed EXE without external Python. No precision/recall threshold was lowered. Positive fixtures explicitly declare their synthetic material; machine routes remain separately review-gated. These fixtures are not an independent vendor recognition benchmark. Vendor corpora, certificates, physical GPU/printer/machine acceptance and code signing are not fabricated.

The original 36 audit items are retained in INTEGRATED_GAP_REPAIR_REGISTER.json. Code implemented, automated acceptance and external qualification are different states. Full product release approval remains false.

## Distribution

Only the joint success of core, all broad shards, and the installed-runtime job allows software-beta promotion. The promoted file has an exact source SHA and SHA-256. A same-version repair test is not an all-versions upgrade/rollback approval.

## Recognition follow-up, 9 September 2026

The existing interpreter now uses source-supported reference end sections, analytic end cuts, local-frame residual primitives, and positive-before-negative feature reconstruction. This repairs low/high end copes, miter cuts, stepped bores and drilled bosses including rotated solids. Round bars and tubes do not acquire phantom drilling features. A selected hypothesis proves only its own features; source authority revocation invalidates cached readiness. Equal-length incompatible axis candidates require review.

The corpus previously compared enum representations incorrectly, masking false positive classes. Metrics now use exact class sets, and the promotion verifier independently recomputes their counts. Case 39 asserts the expected multi-solid rejection; case 44's alleged hole was completely consumed by its cope and its actual ground truth is now NOTCH only; case 20 is a distinct 43-degree cut. These corrections and material declarations are recorded in the corpus itself. No case was removed.

The old phase-2 promotion fixture supplied no project, so the existing PROJECT_PART_NOT_FOUND gate correctly took precedence. The fixture now supplies matching source identities to exercise its intended INTERPRETATION_NOT_READY gate; production code is unchanged.

Local native/corpus evidence is diagnostic until the exact clean-source Windows run succeeds. A generated source SHA, installed binary hash, complete required jobs, 45-case policy and installed-native checks are required for publication. The 317-requirement master acceptance, representative supplier files, DPI/GPU/printer tests, code signing and machine qualification remain distinct open acceptance work; no full-product approval is asserted.

The recent-project placeholder uses the verified painter font directly, not an unavailable historical family baked into a pixmap. Its real Qt icon regression and installed screenshot are included in the release tests. The active product authority now identifies the integrated source branch explicitly.
